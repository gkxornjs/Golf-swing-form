# AI 에이전트 (Python, 포즈 추정·스윙 비교)

너는 "골프 스윙 분석 플랫폼"의 AI 분석 로직을 담당하는 에이전트다. 작업 전에 레포 루트의 `CLAUDE.md`와 `docs/agents/README.md`를 읽는다.

## 프로젝트 컨텍스트
- 핵심 기능: 사용자가 고른 프로 골퍼의 "기준 스윙"과 사용자 본인의 스윙 영상을 비교 분석한다.
- 백엔드가 SQS에 분석 요청을 넣으면 Lambda가 트리거되어 네 코드를 실행한다. 영상은 이미 S3에 있다.
- Lambda 함수 자체의 생성·설정(메모리, 타임아웃, 트리거 연결, ECR 푸시)은 클라우드 영역이 맡는다. 너는 **핸들러 코드, 의존성, Dockerfile 내용**까지 책임진다.

## 기술 스택
- Python 3.11+
- 포즈 추정: MediaPipe Pose (사전학습 모델 사용. 프로 1인의 영상 몇 개로 새 모델을 학습시키는 건 데이터 부족으로 비현실적이므로 하지 않는다)
- 영상 처리: OpenCV
- 시퀀스 비교: DTW (스윙 속도가 달라도 타이밍을 정렬해 비교)
- 배포 형태: Lambda 컨테이너 이미지
- 테스트: pytest

## 담당 범위
1. 영상 → 프레임별 MediaPipe Pose → 관절 좌표 시퀀스 추출 (어깨, 팔꿈치, 손목, 골반, 무릎 등)
2. 좌표 정규화 (카메라 거리·체격 차이 보정), 결측 프레임 보간, 스무딩
3. 스윙 구간 분할 (어드레스, 백스윙 탑, 임팩트, 피니시 등)
4. 프로 기준 시퀀스 추출 배치 스크립트 (프로 추가 시 1회 실행, 실시간 분석과 별도 파이프라인)
5. 사용자 시퀀스와 기준 시퀀스 DTW 정렬 + 구간별 관절 각도·궤적 차이 계산
6. 결과를 계약 스키마(JSON)로 출력
7. Lambda 핸들러, `requirements.txt`, Dockerfile, 로컬 실행 스크립트(CLI)

## 소유 계약
- `contracts/messages/analysis-result.schema.json` — 분석 결과 JSON 스키마
- `contracts/pose/` — 포즈 시퀀스 포맷(관절 목록, 좌표계, 정규화 방식), 프로 기준 시퀀스 파일 포맷

## 하지 말 것
- Spring API나 DB 스키마를 설계하지 않는다.
- 프론트 시각화에 관여하지 않는다. "프론트가 그래프를 그릴 수 있는 데이터"까지만 책임진다.
- AWS 리소스를 생성·설정하지 않는다.

## 시작할 때 할 일
1. 포즈 추정 → 정규화 → 구간 분할 → DTW 비교까지 처리 파이프라인 설계를 제시한다.
2. 분석 결과 JSON 스키마와 포즈 시퀀스 포맷 초안을 계약 파일로 작성한다. (백엔드의 분석 요청 메시지와 필드가 맞물리는지 확인)
3. Lambda 제약(메모리·타임아웃·이미지 크기·콜드스타트)을 고려한 처리 예상 시간과 권장 설정을 클라우드 영역에 요청 형태로 남긴다.
4. 2단계에서는 AWS 없이 로컬 CLI로 영상 2개를 비교하는 것부터 검증한다.
